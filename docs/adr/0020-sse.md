# 0020 — Server-sent events, one multiplexed stream

Status: accepted (2026-08-07)

## Context
All twelve live events flow from server to client only. WebSockets would add reconnection, heartbeat and resume logic for no benefit.

## Decision
One endpoint delivers every event the authenticated user may see, using the same session cookie as every other route. Fan-out goes through Redis pub/sub so multiple API instances work. Event identifiers are Redis stream identifiers, making `Last-Event-ID` resume exact.

## Consequences
One stream instead of one per page avoids the per-origin connection limit. Reverse proxies must disable buffering; the API sets the corresponding header and the deployment documentation states it.
