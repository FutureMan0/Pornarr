# 0021 — arq as the task queue

Status: accepted (2026-08-07)

## Context
The plan suggested Celery or Dramatiq. Both are synchronous-first, while the rest of the stack — FastAPI, httpx, SQLAlchemy, asyncpg — is asynchronous throughout. The worker is overwhelmingly I/O bound.

## Decision
arq, with queues for default, import, transcode and indexer work, and its built-in cron for RSS sync, download polling, profile training and cleanup.

## Consequences
The same clients, sessions and code run in the API and the worker with no synchronous bridge. FFmpeg runs as an asyncio subprocess with a proper timeout and kill path. Flower and the wider Celery ecosystem are unavailable.
